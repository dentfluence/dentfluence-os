00 · Preface

How this was built, and how much to trust each line

Everything below was read out of the working tree: routes/*.php and the two module route files required from them, app/Http/Controllers, app/Services, app/Modules, app/Observers, app/Console/Commands, config/*.php, database/migrations and resources/views. Route names, URIs, middleware chains and group prefixes were extracted with a parser over the route files rather than typed by hand.

Three limits are worth stating plainly, because they change how you should read a status:

No commands were executed. Per project rule, nothing was run — no artisan route:list, no migrations, no tests. Where a claim depends on runtime resolution (route collision order, DB state, feature-flag rows), it is marked verify at runtime rather than asserted.

The local .env is not production. APP_ENV=local, WHATSAPP_DRY_RUN=true, MAIL_MAILER=log, FEATURE_CASE_ACCEPTANCE=true, FEATURE_BLOG_HUB=true. Flag state and send behaviour on the VPS must be read from the VPS.

Feature flags resolve from the database first. config/features.php gives the defaults recorded here; a feature_flags row for a clinic or a global override beats them. Every flag state below is “config default”, not “live value”.

Status pills carry a fixed meaning throughout:

complete wired end to end: UI → route → controller → persistence → read-back partial works, but a documented gap, mismatch or unwired branch exists broken a path that cannot succeed as written not in V1 dormant, retired, or flag-off by design

Gating anomalies visible in the sidebar itself

Six places where the sidebar's @if and the route's middleware disagree. None of these is a guess — each is a direct read of the two files side by side.

SB-1Prescriptionspatients OR treatmentsmodule:prescriptionsA role with Patients-view but no Prescriptions grant sees the item and gets Access Denied on click. The two gates were never reconciled after the prescriptions module row was added (migration 2026-07-25).
SB-2Relationshipsungated — always shownmodule:relationshipSame failure, opposite direction. The blade comment still describes PRE as “an ungated core feature”; it stopped being one on 2026-07-25 when the relationship module row landed.

SB-6Analyticsanalyticsmodule:analyticsGate is consistent, but the destination is not: analytics.* and finance.analytics.* are the same Finance\AnalyticsController methods rendering the same finance.analytics.* views behind two different permissions. Nine pages, two doors, no divergence guard.
